\section{Branches}
\label{sec:branches}

The third educational objective is branching: a branch as a movable pointer
into the commit graph, switching as repointing the working tree, merging as
joining histories.

\subsection{Documented misconceptions and difficulties}

This is the best-documented Git misconception in the seed literature:
learners conceptualise a branch as a directory---\textcquote[p.~10 of the
author copy]{IsomottonenCochez2014}{if asked to checkout a particular
branch, learners might try to move into a branch with the cd command}---%
a difficulty the authors attribute in part to the command-line client, and
against which they recommend visual diagrams of branching and teaching
branches explicitly as pointers into the commit history
\autocite{IsomottonenCochez2014}.
In variation-theory terms: lacking Git's notional machine, the learner
substitutes the file-system model they already master (cf.\ the companion
paper on the terminal \autocite{VTTerminal}).
The directory picture need not even be a substitution: in Subversion a
branch \emph{is} a directory in the repository, conventionally under
\texttt{branches/} \autocite[Ch.~4]{SVNBook}, so a learner who has met
that system carries over a model that was correct there; the open
accounts of \cref{sec:method-instruments} are where the two origins can
be told apart.

\subsection{Candidate critical aspects}
\label{sec:branches-aspects}

The branch-as-directory conception is the one misconception of Git the
literature reports from learners directly, so the first candidate rests
on it; the other two are our decomposition of what the pointer model
requires.

\begin{description}
  \item[A branch is a pointer, not a place]
    The project exists in several concurrent versions; a branch names
    one of them, and switching changes which version the one working
    tree shows, in place.
    The essence is the concurrent versions, not the pointer mechanism:
    a learner who has discerned that the same project is there several
    times over has discerned the aspect, whatever word they use.
    Read off the documented attempt to \texttt{cd} into a branch
    \autocite{IsomottonenCochez2014}, and off the hidden dependency of
    the files on disk on the current branch
    \autocite{Church2014HiddenDependencies}: a learner who has not
    discerned that the place stays and the contents change must look for
    the branch somewhere.
    Tested by the item \emph{seeing another branch}
    (\cref{app:knowledge-items}) and its open twin \emph{the branch
    called feature} (\cref{app:open-items}).
  \item[The graph outlives the pointers]
    Commits exist regardless of which branch points at them; deleting a
    name deletes no history.
    Posited from the object of learning, as the consequence of the
    first aspect that the directory picture gets wrong in the other
    direction (a deleted folder takes its contents with it).
    Tested by the item \emph{deleting a branch}.
  \item[Merging joins histories]
    A merge makes a commit with two parents; it does not copy
    directories.
    Posited from the object of learning.
    Tested by the item \emph{what merging does}; the open item
    \emph{explaining a history} puts a merge in front of the student.
\end{description}

\subsection{Patterns of variation}

\begin{itemize}
  \item Contrast (branch varies, location invariant): switch branches and
    observe \texttt{pwd} unchanged while \texttt{ls} and file contents
    change---the direct refutation of branch-as-directory.
  \item Contrast (pointer varies, graph invariant): delete a merged
    branch and show \texttt{git log --graph} unchanged---the name is gone,
    the commits are not.
  \item Contrast (view varies, state invariant): the same repository state
    in \texttt{git log --graph} and in a graphical history viewer.
  \item Fusion: create, switch, commit, merge---while narrating the
    pointer moves on a drawn commit graph.
\end{itemize}
